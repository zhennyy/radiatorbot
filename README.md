# 🔥 RadiatorPro — магазин в Telegram

Твой личный интернет-магазин отопительного оборудования прямо в Telegram. Покупатель листает каталог, кладёт радиаторы и полотенцесушители в корзину, оформляет заказ и платит — всё в чате с ботом. А ты управляешь всем этим из админки прямо в мини-приложении магазина, даже не открывая код.

Бот умеет разговаривать на двух языках — и с покупателем, и с тобой. Знает имя покупателя и обращается по имени. Умеет подбирать товар с помощью Claude, если человек не знает, что именно ему нужно. И да, он платёжеспособный — принимает оплату через ЮKassa.

## 🧰 Что понадобится

1. **Node.js 22.12+** — `node -v` покажет, что уже стоит. Нет — бери на [nodejs.org](https://nodejs.org).
2. **Токен бота от BotFather**:
   - Пиши [@BotFather](https://t.me/BotFather) в Telegram.
   - `/newbot` → имя → username.
   - Он выдаст токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx` — сохрани его.
3. **Свой chat ID** — чтобы бот знал, кто тут хозяин:
   - Напиши боту что угодно.
   - Открой `https://api.telegram.org/bot<ТВОЙ_ТОКЕН>/getUpdates`, найди `"chat":{"id":...}` — это и есть `OWNER_CHAT_ID`.
4. **Аккаунт в ЮKassa** — чтобы принимать деньги:
   - Регистрируешься на [yookassa.ru](https://yookassa.ru), берёшь `shopId` и секретный ключ в личном кабинете.
5. **Ключ Anthropic API** — чтобы бот умел подбирать товары умом:
   - [console.anthropic.com](https://console.anthropic.com) → API Keys → новый ключ (показывается один раз, сразу сохрани).

## 🚀 Установка

```bash
npm install
```

После установки сам сгенерируется клиент базы (Prisma) — отдельно ничего запускать не нужно.

Создай `.env` в корне проекта:

```env
BOT_TOKEN=токен_от_botfather
BOT_USERNAME=username_бота_без_@
OWNER_CHAT_ID=твой_chat_id
YOOKASSA_SHOP_ID=id_магазина_в_юкассе
YOOKASSA_SECRET_KEY=секретный_ключ_юкассы
ANTHROPIC_API_KEY=твой_ключ_anthropic
WEBHOOK_PORT=3003
PUBLIC_URL=https://radiator.botforall.ru          # адрес сервера (для фото и вебхука)
SHOP_URL=https://radiator.botforall.ru/shop/      # мини-приложение магазина
DB_PATH=/data/radiatorbot/shop.db                 # база и фото — вне папки с кодом
# HOST=127.0.0.1                                  # по умолчанию сервер слушает только localhost (наружу — через nginx)
# ANTHROPIC_BASE_URL=https://ai.botforall.ru:8443 # прокси для Claude API (из России напрямую не пускает)
# TELEGRAM_API_ROOT=https://ai.botforall.ru:8443/tg
# AI_USER_DAY=30        # лимит AI-подборов на покупателя в сутки
# AI_GLOBAL_HOUR=200    # общий лимит AI-подборов в час
```

И в личном кабинете ЮKassa укажи адрес вебхука для `payment.succeeded`:
`https://<твой-домен>/yookassa-webhook`.

## ▶️ Запуск

```bash
npm start
```

Запускается `index.js`: он проверяет `.env` (если не заполнены `BOT_TOKEN` или `OWNER_CHAT_ID` — сразу скажет, чего не хватает), готовит базу, запускает бота, сервер витрины и фоновые задачи. Если в консоли всё зелёное и без ошибок — иди в Telegram, жми `/start`.

Локально бот живёт, пока открыт терминал. Круглосуточно он работает на своём сервере (VPS): код в `/opt/bots/radiatorbot`, база и фото в `/data/radiatorbot` (обновления их не трогают, каждую ночь — резервная копия), ключи — командой `bfa env radiatorbot`, магазин — `https://radiator.botforall.ru/shop/`. Вебхук ЮKassa общий для всех магазинов: `https://botforall.ru/yookassa-webhook`. Установка сервера — в [BotForAll/deploy/README.md](https://github.com/zhennyy/botforall/blob/main/deploy/README.md).

## 💬 Команды бота

| Команда | Что делает | Кому доступно |
| --- | --- | --- |
| `/start` | Здоровается; в первый раз спрашивает имя (и дальше зовёт по нему), во второй — сразу открывает меню | всем |
| `📦 Каталог` | Листаешь товары постранично | всем |
| `🛒 Корзина` | Смотришь корзину, идёшь оформлять | всем |
| `🤖 AI-подбор` | Описал, что нужно — Claude подобрал товар из каталога | всем |
| `📋 Мои заказы` | История заказов со статусами и коротким кодом | всем |
| «✅ Оформить заказ» | Город доставки → адрес → промокод → оплата ЮKassa | всем |
| `🌐 Язык / Language` | Переключить бот на русский или английский | всем |
| `/orders` | Список заказов | владельцу |
| `/addproduct Название \| Описание \| Цена \| Остаток \| Категория` | Добавить товар | владельцу |
| `/stock <id> <остаток>` | Поправить остаток | владельцу |
| `/addpromo КОД ПРОЦЕНТ [ЛИМИТ]`, `/promos`, `/delpromo КОД` | Промокоды: создать, список, выключить | владельцу |
| `/markshipped <id_заказа>` | Отметить заказ отправленным (покупатель получит уведомление) | владельцу |
| `/adddelivery Город Цена` | Добавить/обновить тариф доставки | владельцу |
| `/deliveries` | Список тарифов доставки | владельцу |
| `/deldelivery Город` | Выключить тариф для города | владельцу |

Кстати, про имя и номер заказа — это две разные фишки. Имя бот спрашивает один раз, при первом `/start`, и дальше вставляет его в приветствие, в итог заказа и в уведомления об оплате/отправке. А номер заказа, который видит покупатель, — это не сквозной счётчик вроде «заказ №247» (по нему легко прикинуть, сколько у тебя вообще продаж), а короткий код из 4 символов, например `7K9M`. Внутри базы у заказа, конечно, остаётся и обычный ID — он нужен тебе для управления в админке.

## 🖥 Админка

Живёт внутри мини-приложения магазина (`SHOP_URL`): владелица (`OWNER_CHAT_ID`) открывает магазин из бота и видит дополнительную вкладку админки. Вход — по подписи Telegram, никаких логинов и паролей. Внутри:

- **Товары** — добавить, отредактировать, загрузить фото (с телефона или по ссылке), поправить остатки, английские названия.
- **Заказы** — список, карточка заказа, смена статуса в один клик.
- **Чаты** — переписка с покупателями.
- **Промокоды и доставка** — скидки и тарифы по городам.
- **Статистика** — выручка за 7/30/90 дней, средний чек, топ товаров.
- **Резервная копия** — архив с каталогом, заказами и фото одной кнопкой.

## 🧩 Как это устроено

`index.js` — точка входа: проверяет `.env`, готовит базу, запускает бота, сервер и фоновые задачи. Всё остальное — в `src/`, каждый механизм в своей папке:

| Папка | Что внутри |
| --- | --- |
| `config/` | чтение и проверка `.env` |
| `database/` | подключение к SQLite через Prisma, миграции, стартовые товары и тарифы, разовые правки каталога |
| `customers/`, `settings/` | покупатель (язык, имя) и настройки магазина (доставка) |
| `cart/`, `pricing/`, `orders/` | корзина; цены, доставка по городам и промокоды; заказы — статусы, склад, уведомления, оценки |
| `payments/` | платежи ЮKassa (`yookassa.js`) и создание платежа для заказа (`start.js`) |
| `chat/` | переписка покупатель ⇄ магазин, кнопки статусов под заказом |
| `notifications/`, `schedulers/` | «заканчивается на складе» и проверка раз в час |
| `backup/`, `i18n/` | резервная копия ZIP-архивом, тексты бота RU/EN |
| `legal/` | адреса юридических страниц (политика, согласие, оферта) для ссылок из бота |
| `bot/` | Telegram-бот: `index.js` собирает обработчики из `handlers/` (старт, каталог, корзина, AI-подбор, команды владелицы), `keyboards.js`, оформление в чате (`scenes/checkout.js`), проверка владелицы (`middleware/isOwner.js`) |
| `server/` | Express: API мини-приложения и админки, вебхук ЮKassa, фото товаров (`photos.js`), подпись Telegram и ограничение частоты (`auth.js`) |

Каждый HTTP-маршрут — своя папка в `src/server/routes/` (`shop` — витрина, `checkout` — оформление, `admin-products`, `admin-orders`, `admin-settings` — админка, `yookassa` — вебхук оплаты):

```
src/server/routes/checkout/
  index.js       — маршруты
  validation.js  — проверка входящих данных (middleware перед маршрутом, кладёт результат в request.validated)
  test.js        — тесты этого маршрута
```

Ошибки в маршрутах ловит общий обработчик: наружу уходит короткий JSON, подробности — только в лог.

### База данных

Работа с базой — через ORM [Prisma](https://www.prisma.io) (SQLite): запросы пишутся на JavaScript, без SQL.

```js
const recentOrders = await database.order.findMany({ where: { chat_id: chatId }, orderBy: { created_at: 'desc' }, take: 20 });
```

- `prisma/schema.prisma` — схема всех таблиц (имена полей = колонки в базе).
- `prisma/migrations/*.sql` — изменения структуры; применяются сами при запуске, каждая один раз (учёт — в таблице `_app_migrations`). `001_baseline.sql` — схема, которая уже есть на сервере, `002_order_items_id.sql` даёт позициям заказа свой `id`, `003_order_consent.sql` добавляет заказам время согласия на обработку данных (`consent_at`). Рабочая база обновляется сама, данные остаются на месте.
- Клиент Prisma генерируется автоматически после `npm install` (`npm run db:generate` — вручную).
- Несколько изменений, которые должны пройти вместе (оплата и склад, создание заказа), оборачиваются в `runInTransaction(...)`.

### Мини-приложение

Витрина и админка владелицы — `shop-public/`, без сборщика: браузер грузит ES-модули, сервер отдаёт папку как есть (`/shop`).

```
shop-public/
  index.html   — только разметка; подключает styles/*.css и scripts/main.js
  styles/      — base.css (цвета, светлая/тёмная тема, кнопки) + по файлу на раздел
  scripts/
    main.js, navigation.js        — запуск, вкладки, кнопки Telegram (MainButton/BackButton)
    api.js, state.js, i18n.js, telegram.js — запросы к /shop-api, общее состояние, тексты RU/EN, Telegram SDK
    utils/                        — форматирование цен и дат, экранирование, тосты, делегирование кликов (data-action)
    catalog/, cart/, checkout/, orders/, ai/ — разделы покупателя
    admin/                        — products/, orders/, stats/, chats/, settings/
  legal/       — privacy.html, consent.html, offer.html (+ legal.css): политика, согласие, оферта
```

Кнопки в разметке помечены `data-action="…"`; обработчики регистрируются по имени, слушатель кликов один. Проверка в браузере: `npm run test:ui` (Playwright, скриншоты всех экранов покупателя и владелицы; `-- --compare <папка>` сравнивает с прошлым прогоном).

### Безопасность

Доступ к мини-приложению проверяется подписью Telegram, админ-маршруты доступны только владелице. Платёж подтверждается запросом к ЮKassa с проверкой суммы и метки бота. Есть ограничение частоты запросов, защита от подбора промокодов (не больше 12 попыток в минуту) и от загрузки картинок из внутренней сети. Если платёж не создался, заказ сразу отменяется и не висит в «ждёт оплату». Токены и ключи хранятся только в `.env`.

## 🛡 Персональные данные (152-ФЗ)

Имя, телефон и адрес покупателя — персональные данные, а Telegram — зарубежный сервис. Поэтому:

- **Согласие перед оплатой.** В оформлении витрины — галочка «Я даю согласие на обработку персональных данных» (по умолчанию снята) и строка про оферту и политику со ссылками. Пока галочка не отмечена, «Оплатить» не оформляет заказ, а просит её отметить. Сервер без `consent: true` отвечает 400, время согласия хранится у заказа (`orders.consent_at`). В оформлении в чате — кнопка «✅ Согласен на обработку данных» со ссылкой на текст согласия, без неё кнопки оплаты нет.
- **Владелица в Telegram не получает персональных данных.** В уведомлении о заказе: код, сумма, товары, город или самовывоз, статус и строка «Контакты и адрес — в админке» с кнопкой админки. Нет телефона, адреса и имени, которое покупатель ввёл в боте. Ссылка на профиль Telegram и кнопка «💬 Написать покупателю» остались. То же в `/orders`, в оценке заказа и в переписке (там показывается только имя из профиля Telegram). В резервной копии, которая приходит в чат, нет адресов и телефонов. Телефон и адрес по-прежнему видны в админке: она работает на нашем сервере.
- **Покупателю** в его собственном чате бот, как и раньше, показывает его адрес доставки.
- **Юридические страницы** — шаблоны в `shop-public/legal/`, открываются по адресу `https://<домен>/shop/legal/privacy.html` (а также `consent.html` и `offer.html`).

**Что сделать до запуска:**

1. Заполнить реквизиты в `shop-public/legal/*.html`: всё, что в [КВАДРАТНЫХ СКОБКАХ] (наименование или ФИО ИП, ИНН, ОГРНИП/ОГРН, адрес, email, телефон, служба доставки, сроки), и убрать жёлтую плашку «Шаблон».
2. Подать уведомление в Роскомнадзор об обработке персональных данных ([pd.rkn.gov.ru](https://pd.rkn.gov.ru)) до начала обработки.
3. Отдать тексты юристу на проверку: это шаблоны, а не готовая юридическая консультация.
