# RadiatorPro — магазин в Telegram

Бот интернет-магазина отопительного оборудования (радиаторы, полотенцесушители): каталог, корзина, оформление заказа с доставкой по городам, оплата через ЮKassa, подбор товара с помощью Claude и веб-админка для владельца. Интерфейс двуязычный (русский/английский) — и у покупателя в боте, и у владельца в веб-админке.

## Что понадобится

1. **Node.js 20 или новее** — проверь версию: `node -v`. Если не установлен, скачай с [nodejs.org](https://nodejs.org).
2. **Токен Telegram-бота**:
   - Открой Telegram, напиши [@BotFather](https://t.me/BotFather).
   - Команда `/newbot`, придумай имя и username.
   - BotFather пришлёт токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx` — сохрани его.
3. **Свой chat ID** (чтобы бот знал, кто владелец):
   - Напиши своему боту любое сообщение.
   - Открой в браузере `https://api.telegram.org/bot<ТВОЙ_ТОКЕН>/getUpdates` и найди `"chat":{"id":...}` — это и есть `OWNER_CHAT_ID`.
4. **Магазин в ЮKassa** — для приёма оплаты:
   - Зарегистрируйся на [yookassa.ru](https://yookassa.ru), в личном кабинете возьми `shopId` и секретный ключ.
5. **API-ключ Anthropic** (для AI-подбора товаров):
   - Зайди на [console.anthropic.com](https://console.anthropic.com).
   - В разделе API Keys создай новый ключ и сохрани его (показывается только один раз).

## Установка

Открой терминал в папке проекта и выполни:

```bash
npm install
```

Создай файл `.env` в корне проекта:

```env
BOT_TOKEN=токен_от_botfather
BOT_USERNAME=username_бота_без_@
OWNER_CHAT_ID=твой_chat_id
YOOKASSA_SHOP_ID=id_магазина_в_юкассе
YOOKASSA_SECRET_KEY=секретный_ключ_юкассы
ANTHROPIC_API_KEY=твой_ключ_anthropic
ADMIN_USER=логин_для_веб-админки
ADMIN_PASS=пароль_для_веб-админки
WEBHOOK_PORT=3001
# DB_PATH=/data/shop.db  # опционально, для деплоя (например, на Railway с подключённым Volume)
```

В личном кабинете ЮKassa укажи URL вебхука для события `payment.succeeded`:
`https://<твой-домен>/yookassa-webhook`.

## Запуск

```bash
npm start
```

В консоли появится подтверждение, что бот и сервер вебхуков запущены — значит всё работает. Открой бота в Telegram и напиши `/start`.

Пока скрипт запущен в терминале — бот отвечает. Для постоянной работы 24/7 бот задеплоен на [Railway](https://railway.app) — там переменные окружения задаются в настройках проекта, а `shop.db` хранится на подключённом Volume, чтобы не пропадать при каждом деплое.

## Команды бота

| Команда | Описание | Доступ |
| --- | --- | --- |
| `/start` | Приветствие; при первом заходе бот спрашивает имя (дальше обращается по нему), при повторном — сразу показывает меню | все |
| `📦 Каталог` | Просмотр каталога с пагинацией | все |
| `🛒 Корзина` | Просмотр корзины, переход к оформлению | все |
| `🤖 AI-подбор` | Описываешь, что нужно — Claude подбирает подходящий товар из каталога | все |
| `📋 Мои заказы` | История своих заказов со статусами и кодом каждого заказа | все |
| «✅ Оформить заказ» | Сценарий: выбор города доставки кнопками → адрес → промокод → оплата ЮKassa | все |
| `🌐 Язык / Language` | Переключение интерфейса покупателя между русским и английским | все |
| `/orders` | Список заказов | владелец |
| `/addproduct Название \| Описание \| Цена \| Остаток \| Категория` | Добавить товар | владелец |
| `/stock <id> <остаток>` | Обновить остаток товара | владелец |
| `/markshipped <id_заказа>` | Отметить заказ отправленным (покупателю приходит уведомление) | владелец |
| `/adddelivery Город Цена` | Добавить/обновить тариф доставки для города | владелец |
| `/deliveries` | Список тарифов доставки | владелец |
| `/deldelivery Город` | Отключить тариф для города (дальше действует тариф по умолчанию) | владелец |

Имя покупателя и номер заказа, который он видит, — это разные вещи. Имя бот один раз спрашивает при первом `/start` и запоминает по chat ID; дальше подставляет его в приветствие, в начало итога заказа при оформлении и в уведомления об оплате/отправке. А вместо сквозного номера заказа (`#1`, `#2`, ...) покупателю везде показывается короткий случайный код из 4 символов (буквы и цифры, например `7K9M`) — так по нему нельзя понять, сколько всего заказов в магазине, но на него удобно сослаться в переписке. Внутренний порядковый номер (`id`) никуда не делся — он остаётся в базе и в админке для управления заказами.

## Веб-админка

Доступна по адресу `https://<твой-домен>/admin` (логин и пароль — `ADMIN_USER` / `ADMIN_PASS` из `.env`). Справа вверху — переключатель `RU` / `EN`: меняет язык всего интерфейса админки (выбор запоминается в браузере). Пять вкладок:

- **Товары** — добавление/редактирование, загрузка фото с компьютера или по ссылке, остатки. У каждого товара можно задать название/описание/категорию на английском (поля «на англ.» в форме, кнопка «🌐 EN» у уже добавленных) — если перевод не указан, английский покупатель увидит русское название.
- **Заказы** — фильтр по статусу и поиск (по номеру, коду заказа, адресу или chat ID), карточка заказа по клику на строку (состав, доставка, промокод, оплата), смена статуса, выгрузка в CSV. В английском режиме названия товаров и город доставки показываются переводом, если он задан.
- **Промокоды** — создание кодов со скидкой, включение/отключение.
- **Доставка** — тарифы по городам с инлайн-редактированием цены, тариф по умолчанию для остальных городов. У каждого города тоже можно задать английское название (поле при добавлении, кнопка «🌐 EN» у существующих) — оно используется и в боте при выборе города на английском, и в админке.
- **Аналитика** — выручка и количество заказов за день/неделю/месяц, средний чек, топ товаров.

## Как это устроено

- `bot.js` — точка входа: регистрация команд, сцен, кнопок; AI-подбор через Claude API; запрос и хранение имени покупателя при первом `/start`.
- `db.js` — SQLite (better-sqlite3): схема, миграции (`ALTER TABLE ... ADD COLUMN` с проверкой, чтобы не сломать продовую базу), сид тестовых товаров и тарифов доставки. Здесь же живут вспомогательные функции: `getLang`/`setLang` (язык покупателя), `getName`/`setName` (имя покупателя), `generateOrderCode` (уникальный 4-символьный код заказа), `getCityEn`/`translateCity` (английское название города доставки по русскому).
- `cart.js` — логика корзины.
- `notify.js` — уведомления владельцу о низких остатках.
- `webhook.js` — Express-сервер: приём вебхуков ЮKassa, REST API для админки (`/api/*`), раздача веб-админки (`/admin`) и загруженных фото (`/uploads`).
- `middleware/isOwner.js` — ограничение доступа к владельческим командам.
- `payments/yookassa.js` — создание и проверка платежей через API ЮKassa.
- `scenes/checkout.js` — сценарий оформления заказа (город доставки кнопками → адрес → промокод → оплата); при создании заказа генерирует его код и приветствует покупателя по имени в итоге, если оно указано.
- `i18n.js` — двуязычные тексты для покупателя (RU/EN); переключаются кнопкой "🌐 Язык / Language", выбор сохраняется по chat ID. Команды владельца остаются на русском.
- Названия, описания и категории товаров, а также названия городов доставки можно перевести на английский прямо в админке (поля "на англ." в форме, кнопка "🌐 EN" у уже добавленных) — если перевод не задан, английский покупатель видит русский вариант.
- `admin-public/index.html` — веб-админка, один файл (HTML/CSS/JS без сборки). У неё свой набор двуязычных строк (`ADMIN_STRINGS`) и переключатель RU/EN в шапке — выбор языка хранится в `localStorage` браузера и не связан с языком, который выбрал покупатель в боте.
